\section{Conclusion}
This paper introduces TinyNet, a novel routing protocol tailored for Networked Control Systems, emphasizing Message Delivery Time Determinism over Total Throughput. TinyNet's efficacy in routing messages using minimalistic hardware has been showcased alongside a simulation tool that assesses its performance. A standout feature of TinyNet is its ability to manage message routing in extensively connected networks without relying on a Network Controller or requiring nodes to possess complete network topology knowledge.

The central contribution of this work is the creation of a port-forwarding strategy that utilizes real-time data about queue sizes at subsequent hops. This innovation allows for the intelligent rerouting of packets to circumvent congested network segments.

Determining realistic usage profiles for Networked Control Systems has been challenging due to limited existing research. We plan to gather primary data on practical applications and challenges in this field by consulting industry stakeholders at companies such as Boeing, Airbus, and Moog Inc.

The use of UART presents limitations in our project, specifically in capping the permissible bitrate to only 3.125 Mbps and necessitating a ``configuration-dependent'' environment where all ports must share the same baudrate settings. UART is an implementation choice driven by microcontroller availability; the routing protocol itself is link-layer agnostic, requiring only reliable byte-serial full-duplex delivery on each port. To address these issues, one future direction could include an FPGA-based link layer, implementing a ``co-clocking'' technique for establishing bitrate. In this approach, neither side of a transmission pre-defines a bitrate. Instead, data transfer occurs in a responsive manner: once one side shifts data into a register, it sends an acknowledgment bit, triggering the transmission of the next bit. This method has successfully achieved bitrates of up to 65 Mbps. We have integrated this system with a microcontroller analogous to the ATSAMS70 used in the TinyNet router, achieving similar transmission speeds via a 5-MHz wide parallel bus. This advancement aims to establish a completely stateless, configuration-free system, significantly enhancing the flexibility and scalability of TinyNet's network infrastructure.

In addition to leveraging FPGAs for a stateless link layer, FPGAs can also be used for switching and port-forwarding, exploiting the simplicity of the TinyNet protocol for implementation in Verilog. This effort is expected to surpass the performance of Switched Ethernet while preserving the stateless, fault-tolerant, and adaptive qualities of TinyNet.

Our evaluation also identifies two limitations. First, TinyNet floods packets for which it has no route, so when failures partition the network, traffic addressed to an unreachable destination can congest surviving paths until the hop-count limit is reached; detecting when a destination has become permanently unreachable and suppressing further floods is an open design challenge. Second, for periodic traffic known in advance, single-path routes planned for that traffic deliver lower jitter than TinyNet at the same capacity, so TinyNet is best suited to networks whose traffic or failures cannot be planned for.

The evaluation in this paper is limited to networks of up to 20 nodes. Larger networks offer greater path diversity, which should allow TinyNet's cost-function routing to distribute load more effectively; however, LUT memory grows as $O(N \cdot \Delta)$ per node and behavior under large-scale failures has not been measured, so evaluation at larger scales remains future work.
